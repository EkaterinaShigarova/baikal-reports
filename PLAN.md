# План Baikal LLM Wiki

Цель: воспроизводимая обработка государственных докладов за доступные годы диапазона 2003–2026, связанная Wiki с проверяемыми ссылками, наборы данных и локальный аналитический интерфейс.

## Этапы и критерии приёмки
1. **Контракты и каркас.** CLI, схема источников/наблюдений/Wiki, конфигурация, защита PDF от Git. Тесты схем, единиц, десятичных чисел и запрета несопоставимых сравнений.
2. **Приобретение источников.** Список Drive, официальные каталоги, SHA256, потоковая загрузка, проверка PDF, неизменяемое хранение, повторное использование. Отдельные статусы доступности, подлинности и обработки. SOURCES.md включает каждый год, в том числе неизвестные.
3. **Постраничное извлечение.** Текст, блоки/заголовки, таблицы двух методов, кандидаты продолжений, подписи, изображения и локальные превью; OCR rus+eng при плохом тексте. JSON и Markdown/HTML на каждую страницу, ошибки и возобновление. Проверка на реальных PDF, без загрузки целого документа в LLM.
4. **Данные и QA.** SQLite FTS, CSV/JSON, кандидаты чисел с контекстом, проверенные наблюдения с происхождением, сопоставимость и журнал рецензирования. Пропущенные столбцы/диапазоны не превращаются в достоверные скаляры.
5. **LLM Wiki.** Изучение оригинального gist, схема, правила ingest/query/lint, страницы источников/тем/сущностей, индекс, журнал, сохранение ручных заметок. Локальный необязательный LLM для ограниченных пакетов с валидацией ссылок; без LLM — честно обозначенные доказательные выдержки.
6. **Веб-приложение.** Главная, Wiki, поиск FTS, документы/страницы, таблицы, фильтры, графики проверенных сопоставимых показателей, переходы к источникам. Проверка HTTP API и запуска.
7. **Коллекция и публикация.** Последовательные документы, ограниченное число рабочих процессов, все страницы, отчёт по каждому документу. README для VS Code, CI, обновление новых источников, commit/push этапов, попытка PR.

## Технологии и ресурсы
Python 3.11+, PyMuPDF, pdfplumber, Tesseract rus+eng, SQLite FTS5, FastAPI; веб-интерфейс без CDN. PDF/изображения/SQLite — локально в ignored data/. Стандартный пул 2 процесса, одна страница на задачу. Перезапуск не пересчитывает валидные страницы с той же версией извлекателя. Изменившиеся документы получают новый хеш, прежние версии сохраняются.

## Проверка источников
Google Drive содержит 10 PDF; требуется проверить титулы и содержание. Официальные URL подтверждать только ответами сайтов ведомств, не догадками. Пустой год означает «публикация не проверена», а не «доклада не существует». Доклад 2026 года заранее не предполагается.

## Ограничения и контроль качества
На старте gist.github.com, gist.githubusercontent.com и сайты ведомств блокируются CONNECT 403. Добавлены точные домены в черновик, применение зависит от среды. Чтение методики и внешнее подтверждение подлинности до доступа остаются открытыми. Автоматическая расшифровка графиков/карт не равна достоверным численным данным: сохранять изображения, подписи и статус human_review. Наличие OCR не гарантирует качества; сохранять исходный текст и отчёты.

Каждый этап завершается тестами, обновлением PROGRESS.md и push ветки. Незавершённые функции и страницы указываются явно, а не маскируются общим статусом успеха.
