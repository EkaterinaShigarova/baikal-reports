# Сравнение Qwen 7B с Qwen 1.5B на неизменных входах v2

Зафиксировано до генераций 7B, исходный commit daf21bc. Основные критерии и ожидания — прежний LLM_COMPARISON_PROTOCOL.md; его текст, промпт, доказательства, статьи и валидатор v2 не изменяются. Один запрос на осетра и один на авандельту Селенги, без скрытых повторов, исправления вывода или публикации.

Контроль: runner сверяет SHA256 обоих исходных запусков 1.5B из datasets/llm_comparison_v2.json и полное равенство сообщений system/user, SHA256 статьи, temperature=0, max_tokens=1800. После ответа фактический payload также сравнивается с исходным. Семплирование, контекст 8192, 4 CPU-потока, один слот, batch 256, GPU layers=0 сохраняются. Используется тот же AVX2 llama.cpp и его SHA256. Изменяется модель: закреплённые Qwen2.5-7B-Instruct-GGUF Q4_K_M, два официальных shard, Apache-2.0.

Предусмотрено только техническое изменение бюджета: профиль 7B допускает сумму до 6 ГиБ, RAM limit/available ≥16 ГиБ, резерв диска 3 ГиБ; транспортный таймаут 600 с вместо 180 с, чтобы медленный CPU сам по себе не обрывал ответ. Лимит 2 ГиБ и таймаут 180 с модели 1.5B сохраняются. Таймаут не меняет модельные токены/промпт. Каждый shard проверяется по отдельным опубликованным размеру/SHA256/GGUF; runtime загружает оба без объединения/дублирования модели. До загрузки проверяются официальный ID репозитория, ревизия и лицензия. Одновременно максимум два фиксированных потока загрузки, повторных запросов для обхода сети нет.

Отдельно считаются: реальные ответы; принятые/отклонённые программно; пригодные после смысловой сверки; новые поддержанные детали; ложная новизна, неверная атрибуция, придуманные значения/конфликты, пропущенные ограничения. Успешная подстановка цитаты по ID не означает поддержки утверждения. Пустое воздержание не считается новым знанием. Все принятые ответы остаются неопубликованными черновиками; экспертный статус не присваивается.

Сравнение проводится с 1.5B v2; более ранний v1 включается в таблицу только как исторический контекст, поскольку его входы отличались. Память — пиковый дочерний RSS, время — от старта до завершения сервера плюс отдельные запросы; загрузка весов отдельно. Два случая не дают общей оценки модели. Если 7B не обеспечивает пригодного результата, классифицировать конкретные отказы (формат, семантика, новизна, контекст/таблица, программный false positive), сохранить их и выбрать один следующий ограниченный этап вместо повторения промптов.

Дополнение до генераций: после медленной первоначальной передачи двух файлов сохранённые префиксы продолжаются по HTTP Range, максимум четыре соединения, диапазоны по 256 МиБ, без автоматических повторов. Поддержка подтверждена одним пробным байтом (HTTP 206 с точным Content-Range). Каждый диапазон проверяется по началу/концу/размеру; финальная сборка каждого shard по полному официальному SHA256/GGUF. Префиксы и диапазоны сохраняются, рабочий диск проверяется для двух копий весов плюс 3 ГиБ резерва (около 11,72 ГиБ). Изменяется только техническая загрузка; сообщения модели, проверки и критерии сравнения неизменны.
