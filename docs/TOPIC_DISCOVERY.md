# Экспериментальное обнаружение тем и доказательные планы

Продолжение от `f57c375`. [Предварительный протокол](TOPIC_DISCOVERY_PROTOCOL.md) разделяет программный контроль, настоящую генерацию и последующую содержательную сверку. Действующие статьи, каталог, числовые наблюдения и PDF не обновляются этим режимом.

### Редакционная очередь и причины ограничений

- **Новые статьи:** два прежних связных черновика [порты](drafts/ports-and-petroleum.md) и [коммунальные стоки](drafts/municipal-wastewater.md) остаются пригодными для отдельного рассмотрения по прежнему источниковому разбору. Неудачный модельный план их не заменяет. Новых модельных планов нет; папка discovery содержит пояснение режима.
- **Дополнения:** использовать ранее сверенный кандидат `SOURCE-COAST-2018`, а не модельную отдельную статью. Два кандидата Селенги также сохраняются в [прежнем реестре](../datasets/editorial_scientific_review.json).
- **Противоречия:** те же issue-ID phenol-counts, seal-methods, selenga-methods в существующем реестре. Новая система научных статусов и ложное человеческое одобрение не создавались.
- **Отсутствующие доказательства:** D04 требует входных/выходных концентраций, массы/расхода, режима и методики очистки; из объёма воды эффективность не восстанавливается.

Проблема не только в модели. В текущей схеме одна связь выбирается из overlaps/distinct_scope, хотя частичное совпадение фактов и самостоятельный предмет могут сосуществовать. Это консервативно заблокировало D01/D02; нельзя считать их неправильными решениями о направлении только из-за этого gate. Вместе с тем их обоснования и повторяющиеся разделы недостаточны. Правила после получения ответов не ослаблялись.

Подбор по общей PDF-странице вынес в D01 Северный Байкал рядом с портами, хотя это разные территории; последний выбранный блок статьи иногда является списком ссылок, а не разделом ограничений. Частичный контекст и такая гранулярность поиска ухудшают сравнение. Обязательные вопросы сохранены отдельными карточками, но это не исправляет качество выбора предмета моделью. D03 содержит реальную ошибку чтения уже переданного абзаца, D04 — игнорирование явного ограничения. Одним увеличением числа похожих промптов эти причины не устранить.

Следующий этап: связать предмет/показатель/территорию с проверенными атомарными реестрами, разделить **перекрытие фактов** и **отношение предметов**, подбирать блоки с учётом заголовков и нескольких тем на странице. Затем независимо проверить небольшой новый набор, включая обязанность отказаться от вывода при нехватке доказательств. Обход gate или немедленная публикация старых ответов не являются решением.

## Что делает механизм

1. `scan` читает **готовые JSON страниц**, ищет повторяющиеся нумерованные заголовки разных документов и сохраняет тематические зацепки. Новое название не требуется заранее добавлять в Python или в каталог. Это поиск мест для исследования, а не установленная научная тема.
2. Для выбранной зацепки составляется пакет точных выдержек, годов доклада/публикации, физических страниц, SHA256 и вопросов/ограничений. В этом спринте пакеты отобраны и сверены заранее; свободная автоматическая атомизация неизвестной таблицы не заявляется.
3. Общий подбор контекста читает весь каталог, включая очередь без статей, находит две релевантные статьи по названиям/содержанию и пересечению страниц источников. Передаются точные абзацы с хешами версий и внутренние связи. Пересечение источников — сигнал связи, а не одинаковости предметов. Например, одна страница обзора может описывать несколько районов.
4. Qwen предлагает отдельную тему, дополнение существующей или отложенное решение. Она выбирает evidence-ID, связи со статьями и структуру. Модель не переписывает проверенные числа и цитаты; программа подставляет их из неизменных источников.
5. Gate отклоняет неизвестные ID, неподдержанные числа в свободном названии/объяснении, пропуск обязательных ограничений, отдельную статью по единственному документу и явный/неразрешённый дубликат. Несколько документов — необходимый, **не достаточный** критерий научной обеспеченности.
6. Технически допустимые предложения сохраняются существующим `save_packet`, версии статей — `archive_article`. Доказательные Markdown-планы лежат в `docs/drafts/discovery/`; два прежних полноценных черновика остаются отдельно и неизменно в `docs/drafts/`.

У планов нет экспертного статуса и решения редактора. Изменения в Wiki не применяются. Программа не определяет полноту знания всей статьи по двум показанным абзацам, не считает отсутствие слова доказательством новизны, не подтверждает сравнительный временной ряд и не переводит кандидаты в observations.

## Как воспроизвести без повторной обработки PDF

В установленном окружении из корня проекта:

```bash
python scripts/discover_topics.py --help
python scripts/discover_topics.py --scan --output data/topic-scan.json
python scripts/check_topic_discovery.py --require-local
```

`scan` не вызывает модель, не открывает PDF и не переписывает checkpoint. Он откажется перезаписывать уже существующий output; для следующего отчёта выберите другое имя. После добавления PDF используйте **общий scan**: он сопоставляет заголовки разных документов. Технический фильтр `--source ID` читает один источник, но при текущем условии «несколько документов» не выдаёт тематических зацепок; это только диагностика прочитанных страниц, не работающий отбор тем нового PDF. Единственный новый заголовок без повторов также пока не обнаруживается этим методом. Нулевой результат не означает отсутствия сведений.

Для исследовательского эксперимента подготовка отдельно сохраняет неизменные входы:

```bash
python scripts/discover_topics.py --prepare --output data/topic-manifest.json
```

Настраиваемый `--tasks` принимает путь к JSON по структуре [проверочного набора](../datasets/topic_discovery_tasks.json); заголовки тем в коде не зашиты. Заменять только expected недостаточно: источники, цитаты и научные ограничения необходимо действительно проверить. По умолчанию используются четыре уже выполненные задачи. `--run --experiment ID --output НОВЫЙ_ФАЙЛ.json` — отдельный реальный запуск, не обычное добавление доклада. ID берётся из манифеста. Прежние слоты уже израсходованы, повтор автоматически блокируется. Не менять протокол ради обхода этой защиты.

## Реальный путь будущего PDF

Сначала проверить подлинность и метаданные, отсутствие дубликата и добавить источник штатным `add-source`. Затем `ingest --source ID` получает оригинал и создаёт/продолжает checkpoint. Новое извлечение в этом спринте не запускалось. Доступ к новому адресу и корректность сложных таблиц требуют отдельной проверки.

После этого доступны существующие `propose-updates --source ID` для известных маршрутов и новый **общий scan** для повторяющихся заголовков, в том числе без маршрута. Их результаты пока **не соединены автономно** с проверкой произвольных фактов: нужно выбрать содержательные страницы, отделить наблюдения от планов/прогнозов, проверить год, единицы, территорию и создать пакет `--tasks`. Далее prepare → ограниченный локальный run → проверка источников и смыслов → редакционное рассмотрение.

Для дополнения действующей статьи остаётся прежний механизм `prepare-change`/`apply-change` с настоящим отдельным решением и точными версиями. **Новый доказательный план не является совместимым принятым draft-ID для этих команд.** Перенос в этот формат требует отдельной сверки и преобразования, здесь не реализован. Публикация новой статьи также требует отдельной процедуры добавления в каталог и реестры. Ни один из этих переходов не выполняется автоматически.

Для полной автономности остаются: извлечение и проверка произвольных атомарных фактов/таблиц, широкий поиск семантических дубликатов, проверка полноты реестров и методик, преобразование проверенного плана в содержательный синтез и редакционные переходы. Текущий механизм — первоначальный воспроизводимый отбор, не законченный автономный научный автор.

## Выполненные проверки

Пройдены 186/186 unittest и Wiki lint без ошибок; прежние предупреждения о недостающих годах сохранены. Дополнительно сверены 162 научные ссылки, 47 привязок энциклопедии, все 168 наблюдений, 18 прежних редакционных выдержек. Новый контроль сверил четыре локальные записи настоящих ответов, 12 ссылок доказательных пакетов и восемь примеров заголовков, SHA256 семи PDF. Проверены 153 относительные Markdown-ссылки изменённой документации, включая 17 физических PDF-якорей.

В отдельной копии без data проверка честно показывает ноль локальных прочитанных источников/запусков; режим require-local отказывает. Положительный тест генератора выполнялся только в изолированном fixture: точные цитаты, физические страницы, полные архивы с непустыми заметками и отсутствие записи в observations. Это не принятый реальный ответ модели.

Неизменны 178 защищённых файлов, все 49 Wiki-файлов/22 статьи, 3878 checkpoint по размеру/mtime, 11 PDF по SHA256, 168 наблюдений и оба прежних связных черновика. Сайт, опубликованный каталог и main не менялись.
