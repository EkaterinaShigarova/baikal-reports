# Эксперимент: новизна без переписывания фактов

Режим дополняет source-first и повторно использует три сохранённые записи, а не повторяет извлечение. [Критерии до запуска](NOVELTY_PROTOCOL.md). Итоги: [LLM_EVALUATION.md](LLM_EVALUATION.md) и [структурированный отчёт](../datasets/novelty_evaluation.json).

## Что изменено

В прежнем ответе два объяснения ссылались на чужое значение и территорию, а ответ оборвался из-за заполнения контекста. Новый режим передаёт отдельную запись для каждого fact-ID с SHA256 всей записи, точной ячейкой таблицы, статистикой mean, раздельными годами, единицами и территорией. Точные цитаты хранятся один раз; статья передаётся целиком как абзацы с ID, включая ручные заметки. Прежняя сверка источников проверяется повторно программно, её решения не выдаются за новую экспертную рецензию.

Модель выбирает класс отношения и абзацы статьи. Объяснение содержит ссылку на собственный fact-ID и тип отношения; это **не свободная научная проза модели**. Программа отображает исходный факт и выбранные абзацы, а краткое пояснение создаёт из явно обозначенного шаблона. Неизменные значения и ограничения берутся из прежних записей/сверки. Модель не получает эталонных меток из протокола.

Таким способом невозможно незаметно записать в объяснение чужое число или год: свободные поля запрещены, перекрёстные ID отвергаются, исходные привязки проверяются по содержанию и SHA256. При этом выбор неверного абзаца или ошибочной категории остаётся возможным. Программное прохождение не означает правильного понимания статьи.

## Воспроизведение в подготовленной среде

Нужны существующая локальная коллекция, контрольные точки и исходные журналы предыдущего эксперимента, указанные в datasets/typed_facts_evaluation.json, а также прежние проверенные веса/llama.cpp. Публичного checkout без ignored data недостаточно. Ничего скачивать или повторно обрабатывать для этого режима не нужно. Заменять отсутствующие реальные журналы тестовыми запрещено.

Из корня проекта, в установленном Python-окружении:

```bash
python scripts/evaluate_novelty.py --help
python scripts/evaluate_novelty.py --prepare --output data/llm-evaluation/novelty-prepared-d8d4fe3.json
```

Подготовка не вызывает генерацию. Она записывает content-addressed manifest с протоколом, кодом, входами, моделью, статьёй и SHA256 старого отчёта. Следующая команда относится к **единственному** ограниченному опыту этого спринта:

```bash
python scripts/evaluate_novelty.py --run --experiment 1f2cda4825e0f1855bbf76acff6071693dd82c93440222b985b0a45215ab31ad --output data/llm-evaluation/novelty-run-d8d4fe3.json
```

После выполненного опыта повтор той же попытки запрещён. Если выходной файл уже существует, команда также останавливается. На другом подготовленном компьютере с тем же кодом и исходными данными manifest должен совпасть; время и побитовое совпадение генерации на другом CPU не гарантируются. Для нового сравнительного исследования нужен отдельный протокол, а не обход блокировки повтора.

Результат сохраняется в `data/wiki_updates/novelty_runs/`; исходный HTTP-ответ, запрос, токены, ошибки, SHA256 и журнал сервера остаются локально. Сервер работает только на 127.0.0.1, документы не отправляются внешнему API. Нативный токенизатор резервирует полный бюджет ответа до расходования единственного слота генерации.

## Отдельная смысловая проверка и черновик

`--run` никогда не создаёт дополнение автоматически. Для `--draft` требуется отдельный JSON-реестр со статусом `semantic_comparison_non_expert`, `expert_review: false`, точным `run_id`, решением supported/rejected и содержательной причиной по каждому факту. Отдельно нужно подтвердить сохранение каждого известного противоречия. Формат использованного решения и его хеш доступны в структурированном отчёте. Это не человеческое редакционное одобрение.

Команда `--draft --experiment … --run-record … --semantic-review … --output …` только сохраняет исходные допущенные факты, полную предыдущую статью, источники, ограничения и решения в `data/wiki_updates/novelty_drafts/`. Она не подключена к автоматической публикации. Исходные формулировки фактов сохранены дословно; перед публикацией нужно явно написать «среднее», уже заданное в поле statistic. Не менять числа, спорные максимумы или наблюдения.

Единственный набор из трёх новых деталей не доказывает надёжность на повторах, противоречиях и недостаточных доказательствах. Для них нужен отдельный сбалансированный контрольный набор. Новизна относительно статьи не означает научную новизну результата измерения.

## Итог первого запуска

Получен один полный реальный ответ, 6318/342 токена, 346,314 с. Программно приняты три решения, смыслово верных — 0: модель во всех случаях выбрала insufficient_evidence вместо new_detail. Для известного конфликта она указала только заголовок. Все решения отдельно проверены и отклонены в этом объёме; `--draft` не вызывался, черновиков нет. Неизменные исходные факты и действующая статья сохранены. Безопасность ссылочных полей улучшена, качество классификации пока недостаточно.

Проверка происхождения отчёта, сохранённого ответа и прежних фактов:

```bash
python scripts/check_novelty.py --require-local
```

Без `--require-local` доступны проверки публичных записей, цитат, ячеек, версий и структуры; при наличии локального ответа он проверяется дополнительно. Проверка хешей/реестра не является новой научной экспертизой или независимым доказательством правильности смысловой оценки.
