# Перенос конвейера на новые документы и темы

Аудит от `d048220` не меняет архитектуру и не демонстрирует полностью автономную научную Wiki. Он разделяет общие компоненты, настройки тем и специализированные экспериментальные сценарии. Реальный корпус и опубликованные статьи сохранены.

## Что уже общее

| Компонент | Возможность | Граница |
| --- | --- | --- |
| [acquire.py](../baikal/acquire.py) | Получение по реестру источников, Google Drive/HTTPS, проверка SHA256 сохранённого PDF | Доступ к будущему URL, подлинность и правильность метаданных не гарантированы |
| [extract.py](../baikal/extract.py) | Число страниц берётся из нового PDF; извлечение/OCR/таблицы и продолжение по SHA256/версии | OCR зависит от языка/среды; сложные заголовки и связи таблиц требуют сверки |
| [updates.py](../baikal/updates.py) | Темы читаются из конфигурации, изменённые страницы дают предложения, прежние статьи архивируются | Лексический маршрут не определяет научную новизну; неизвестная тема требует разбора |
| [cross_topic.py](../baikal/cross_topic.py) | Сравнение переданных признаков без списка допустимых экологических тем | Признаки должны быть извлечены/проверены; неизвестные методы не восстанавливаются сами |
| [draft_review.py](../baikal/draft_review.py) | Проверка произвольного манифеста черновиков и источников | Проверяет происхождение и ограничения статуса, не смысловую истинность автоматически |

Для нового PDF с уже поддерживаемого источника конвейер не требует отдельной ветви Python-кода по его ID. Нужны запись в `config/sources.json`, проверенные метаданные и доступный файл. Для новой темы нужны каталог и правила в JSON-конфигурации, а не специальный Python-обработчик её названия. Это не означает, что программа сама открывает новую научную тему или выбирает правильную методику.

## Воспроизводимая изолированная проверка

Скрипт [audit_pipeline_transfer.py](../scripts/audit_pipeline_transfer.py) создаёт во временной папке **синтетический двухстраничный PDF** с родным текстовым слоем и неизвестным ID источника. Тема `forest-transfer-control` задаётся только конфигурацией. Это тестовый контроль, не экологический доклад или реальные измерения.

Последовательно проверены существующие функции:

1. Получение неизменного локального PDF через ветвь кэша загрузчика. Сеть запрещена тестовым перехватчиком; новая HTTPS-загрузка **не проверялась**.
2. Извлечение одной страницы, затем продолжение до двух. Первая контрольная точка сохранена по SHA256 и времени изменения; повторно используется одна готовая страница.
3. Формирование одного предложения по новой теме через конфигурацию. Повтор тех же страниц даёт ноль новых предложений.
4. После настройки отсутствующего термина получены два уведомления об отсутствии маршрута. Это диагностируемый пробел, а не автоматически новая статья.
5. Общая функция сравнения принимает признаки лесного показателя без изменения её кода. Это синтетический структурный контроль, не доказательство научной сопоставимости лесных данных.
6. Текст и непустая область заметок предыдущей тестовой статьи, а также тестовый reviewed набор не изменены. Публикаций и LLM-вызовов нет.

Сохранён [результат](../datasets/pipeline_transfer_audit.json), помеченный `test_only=true`, с SHA256 скрипта. Число извлечённых страниц в сводке означает итоговое количество готовых страниц, а не число заново обработанных при продолжении. Синтетические два листа не прибавляются к 3878 страницам или 11 реальным PDF.

Запуск в установленной среде:

```bash
python scripts/audit_pipeline_transfer.py
```

Скрипт использует временную папку, не загружает документы, не запускает модель и не изменяет реальный корпус. Для сохранения отчёта есть `--output НОВЫЙ_ПУТЬ`; существующий файл не перезаписывается. Это не команда добавления настоящего доклада.

## Ограничения, которые нельзя скрывать

- Допустимые официальные домены и начальные страницы поиска сейчас заданы константами в `acquire.py`. Документ с нового официального домена может потребовать проверенного изменения списка; для каждого нового PDF с существующего домена отдельное изменение не требуется. Автоматическая полнота обнаружения докладов не доказана.
- Разбор титула/года эвристический; год наблюдения и публикации нельзя надёжно восстановить только из имени файла. Новому отчёту нужна проверка метаданных; региональному обзору могут потребоваться границы Байкальского раздела в конфигурации.
- Лексические правила охватывают заданные темы. Неизвестное содержание даёт уведомление; автоматическое открытие тем и разрешение синонимов не завершены.
- Предложения обрабатывают ограниченный пакет изменённых страниц; активный пакет темы сохраняет не более 12 выдержек. Предшествующие пакеты остаются в журнале, но текущая выборка не является полным объединением всех доказательств документа или Wiki.
- Эксперименты `evaluate_coverage.py`/`evaluate_cross_topic.py` закреплены за своими наборами и слотами, последний — за T11. Это воспроизводимые исследовательские сценарии, **не универсальный запуск LLM для любого нового доклада**. Их не следует обходить или переписывать ради повторов удачных случаев.
- Реестры утверждений частичные и предварительно сверены. Надёжное самостоятельное извлечение показателя, года, территории и метода из произвольных таблиц пока не установлено. Формат JSON не заменяет доказательства.
- Имеющийся `prepare-change` предназначен для конкретного дополнения существующей статьи; [editorial.py](../baikal/editorial.py) прямо требует отдельный процесс для новых статей. Подготовленные черновики этим процессом не публиковались. Для их принятия нужно отдельное решение и внесение в каталог/реестры с сохранением происхождения.

Итог: переносимость извлечения и конфигурируемой маршрутизации технически подтверждена в ограниченном локальном контроле. Научная универсальность, новая сетевая загрузка, произвольная генерация и автономная публикация этим тестом не подтверждены. Эти границы не требуют переписывать работающий конвейер; следующий этап должен улучшать отдельные проверяемые звенья.
