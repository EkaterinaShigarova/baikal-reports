# Проверка локального LLM-обновления знаний

Дата: 22.10.2026. Исходный commit: `e8497fdc125a95c37b2e5b2e824df8d81af12b5d`.

**Основной эксперимент не завершён: настоящая языковая модель не загружалась и не запускалась.** Вычислительных ресурсов достаточно для небольшого CPU-эксперимента, но доступ к проверенным источникам весов блокирует сетевой прокси. Подготовка входов и синтетические тесты не считаются генерацией модели. Машиночитаемый протокол: [llm_evaluation.json](../datasets/llm_evaluation.json).

Для воспроизводимого запуска установлены пределы: GGUF не более 2 ГиБ, RAM не менее 8 ГиБ с 4 ГиБ доступной памяти, запас диска не менее 2 ГиБ после загрузки; CPU — четыре потока, контекст — 8192 токена, GPU — отключён. Это план, не измеренный расход инференса. Веса, runtime и большие пакеты в этом спринте не скачивались.

Прокси возвращает `Tunnel connection failed: 403 Forbidden` при CONNECT к следующим адресам:

- `https://modelscope.cn/api/v1/models/Qwen/Qwen2.5-1.5B-Instruct-GGUF/repo/files?Revision=master&Recursive=true`

- `https://registry.ollama.ai/v2/library/qwen2.5/manifests/1.5b`

Это отказ прокси установить туннель, а не установленная ошибка авторизации на сервере модели. Причина политики прокси не раскрыта. Доступны метаданные PyPI и GitHub: для llama-cpp-python опубликована версия 0.3.36, исходный архив 76 589 250 байт; проверен tag llama.cpp v0.7.0, commit `620d2225cc436ab0b001e3200e590e3b286ef9ab`. Сборка/исполнение runtime не проверялись: без весов они не дадут результата основного эксперимента.

Запросы к внешним сервисам содержали только адреса публичных файлов/метаданных, без экологических документов и фрагментов Wiki. Платные API не использовались.

## Подготовленные реальные доказательства

Команда подготовки использует существующий [протокол предложений](../datasets/update_workflow_test.json) и `propose-updates`. Два входа сохранены в ignored `data/wiki_updates/evaluation_inputs/`, исходные и уточнённые предложения — отдельно по SHA256. В них включены текущая статья, кандидаты каталога, версии источников, физические страницы, точные цитаты и известные проблемы. Ручные заметки не передаются как проверенные знания, но входят в контрольную сумму сохраняемой версии.

| Случай | Страницы PDF | Референсные ожидания будущей проверки |
| --- | --- | --- |
| Байкальский осётр | 2016/222, 2024/67 | Отличить уже изложенный общий выпуск от детали о части молоди и её навеске; не считать выпуск выживаемостью. Не приписывать осетру сведения о хариусе из соседней колонки и не превращать прогноз в наблюдение. |
| Авандельта Селенги | 2015/26 | Сохранить оба варианта порядка максимумов БП/канцерогенов. Расхождение уже описано в статье и реестре: его повторное обнаружение не является новым противоречием. |

Эти ожидания основаны на сохранённых страницах и статьях; это не независимая экспертная разметка. Период наблюдения остаётся отдельным полем; отсутствие значения не заменяется годом доклада. Год публикации передаётся только при наличии метаданных. В готовых входах обе статьи поместились полностью в лимит основного текста 6000 символов.

## Сравнение с лексическим механизмом

Прежний изолированный опыт дал 10 лексических предложений по семи темам. Это не десять результатов LLM. Подготовлены два случая для настоящей генерации; модельных предложений — **0**.

При проверке входов установлено:

1. Прежний запрос содержал выдержки без текущей статьи. По такому входу нельзя достоверно определить, что уже известно Wiki. Режим `--assess-update` теперь добавляет ограниченный контекст и отдельную классификацию `new_detail`, `already_present`, `uncertain`.
2. Лексическое окно Селенги (1209 символов) не включало нужную строку таблицы 2015 года. Для теста выделен более полный, но ограниченный фрагмент до следующего раздела; оригинальное предложение не переписано. Это подготовка доказательств, не улучшение результата модели.
3. Окно страницы 2024/67 включает сведения о другом виде рыбы из соседней колонки. Их смысловое разграничение необходимо оценить при настоящей генерации; автоматическая маршрутизация не устраняет смешение колонок.

Для каждого ответа нужно отдельно оценить восемь критериев: понимание фрагмента, новизну относительно предоставленной статьи, выбор темы, связность дополнения, точность цитат, отсутствие вымышленных чисел/лет, обращение с противоречиями и сохранение неопределённости. Сейчас по всем восьми критериям **результат модели не оценён**. Число её ошибок и галлюцинаций неизвестно; ноль ответов не означает нулевую ошибку. Преимущество над лексическим поиском не установлено.

## Воспроизводимый запуск на подходящем компьютере

Инструкция предназначена для Linux или WSL2 с установленным проектом и сохранёнными контрольными точками. Предложения и входы не требуют нового PDF/OCR. Сборка runtime и инференс по инструкции пока не испытаны в этой среде.

```bash
python scripts/evaluate_local_llm.py --prepare-only
python scripts/download_evaluation_model.py --metadata-only
```

Вторая команда сейчас воспроизводит CONNECT 403. На компьютере с доступом к официальному репозиторию она проверяет лицензионные метаданные Apache-2.0, точную ревизию, размер, опубликованный LFS SHA256 и ресурсы. Только после успешного контроля выполнить:

```bash
python scripts/download_evaluation_model.py
```

Загрузка потоковая, ограничена 2 ГиБ и объявленным размером, проверяет SHA256 и GGUF. Повторно существующая корректная модель не скачивается; несовпадающий файл не перезаписывается. Веса и файл происхождения сохраняются в ignored `data/models/`. При запрещённом перенаправлении нужно установить фактический адрес CDN и настроить доступ; одного доступного сайта метаданных недостаточно.

Для бесплатного CPU runtime нужны Git, C++ compiler и CMake. После установки этих инструментов:

```bash
git clone --depth 1 --branch v0.7.0 https://github.com/ggml-org/llama.cpp.git data/llm-runtime/llama.cpp
git -C data/llm-runtime/llama.cpp rev-parse HEAD
# Ожидается 620d2225cc436ab0b001e3200e590e3b286ef9ab
cmake -S data/llm-runtime/llama.cpp -B data/llm-runtime/build -DCMAKE_BUILD_TYPE=Release -DGGML_CUDA=OFF -DLLAMA_CURL=OFF -DLLAMA_BUILD_TESTS=OFF -DLLAMA_BUILD_SERVER=ON
cmake --build data/llm-runtime/build --target llama-server -j 4
data/llm-runtime/build/bin/llama-server --version
```

Сверить checksum модели с `.source.json` и официальными метаданными; подставить опубликованный SHA256 вместо `MODEL_SHA256`:

```bash
python scripts/evaluate_local_llm.py --run \
  --model-file data/models/qwen2.5-1.5b-instruct-q4_k_m.gguf \
  --model-sha256 MODEL_SHA256 \
  --server-binary data/llm-runtime/build/bin/llama-server \
  --output data/llm-evaluation/result-run-01.json
```

Скрипт сам запускает и завершает локальный runtime, привязывает сервер к 127.0.0.1, проверяет размер/хеш модели и сохраняет хеш/версию бинарного файла, параметры, время и пиковый RSS дочерних процессов. Произвольного внешнего endpoint у этой команды нет. Встроенный клиент не использует прокси для loopback. Входы, сырые ответы, ошибки JSON/цитат, usage и отклонённые результаты остаются в ignored `data/wiki_updates/`; серверные журналы получают отдельные имена. Ключ API в эти записи не сохраняется.

Наличие ответа сервера означает генерацию в зафиксированном runtime, но не научную достоверность. Даже корректный JSON с действительной цитатой может содержать неверную интерпретацию. Все черновики требуют содержательного разбора; `finish_reason=length`, устаревший источник/статья и неподдержанные ссылки отклоняются с сохранением ответа.

## Редакционное принятие без автоматической публикации

Реального человеческого одобрения и применения дополнений к проекту в этом спринте **не было**. Переход проверен только синтетическими fixtures в изолированных каталогах, включая непустые заметки и откат ошибки записи. Это не имитация научной рецензии.

После будущей генерации можно подготовить дополнение из выбранных кандидатов `new_detail` (индексы от нуля):

```bash
python -m baikal prepare-change --draft DRAFT_ID --claims 0
```

Открыть полученный пакет `data/wiki_updates/changes/CHANGE_ID.json`: проверить `new_text`, выбранные утверждения, ссылки, ограничения и контрольные суммы. Подготовка ничего не меняет в статье. Редактор должен сам сверить смысл, год, территорию, единицы и неопределённость. Следующий шаблон намеренно **не является одобрением** и будет отклонён до реального заполнения:

```json
{
  "change_id": "CHANGE_ID",
  "decision": "approve",
  "review_kind": "editorial",
  "reviewed_by": "",
  "reviewed_at": "YYYY-MM-DD",
  "source_semantics_checked": false,
  "uncertainties_preserved": false,
  "test_only": false
}
```

После реального редакционного решения:

```bash
python -m baikal apply-change --change CHANGE_ID --approval data/editorial-approval.json
python -m baikal build
python -m baikal lint
```

Изменение привязано к точной версии статьи и immutable-черновика; устаревший источник, текст или неподдержанная цитата блокируют применение. Старый основной текст сохраняется, дополнение помещается перед неизменными HUMAN NOTES, предыдущая версия архивируется. Источники добавляются к прежнему происхождению, решение фиксируется в `datasets/editorial_changes.json` и журнале Wiki. Ошибка записи вызывает откат. Повторное применение не дублирует дополнение.

Прежний реестр научной проверки не переписывается: изменившийся основной текст теряет действующий статус прежней сверки и требует проверки дополнения. Редакционное принятие не даёт статуса специалиста и не добавляет числа в observations. Тестовые одобрения `test_only=true` запрещены в настоящем репозитории. Новые статьи требуют отдельного редакционного процесса, а не автоматического создания из кандидата.

## Сохранность и следующий шаг

Все 22 статьи, реестры научной проверки, 168 наблюдений и 3878 контрольных точек сохраняются. Исходные PDF/OCR не обрабатывались повторно. Проверяются тесты, lint, 162 доказательные ссылки аудита, 47 прежних записей энциклопедии и 168 числовых записей. Подробные итоги проверок — в PROGRESS.md.

Следующий необходимый шаг — получить доступ к официальным весам либо перенести проверенную модель на подходящий компьютер и выполнить две реальные генерации. Затем провести содержательный разбор каждого ответа по восьми критериям, зафиксировать ошибки и только после этого решать вопрос редакционного применения. До этого работоспособность интеллектуального обновления настоящей моделью **не подтверждена**. Новых аналитических статей в данном спринте нет.
