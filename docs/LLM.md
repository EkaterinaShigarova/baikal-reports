# Необязательный семантический синтез

Обработка PDF, OCR, Wiki с выдержками, поиск и графики не требуют LLM API. Команда `python -m baikal synthesize air` включает дополнительный синтез ограниченного пакета доказательств (до 12 выдержек, максимум 1800 токенов ответа).

Бесплатный локальный вариант: установить Ollama отдельно, загрузить подходящую модель, например qwen2.5:7b; задать `BAIKAL_LLM_URL=http://127.0.0.1:11434/v1/chat/completions` и `BAIKAL_LLM_MODEL=qwen2.5:7b`. Требуются память/диск для выбранной модели; установка модели не выполнена в облачной проверке. Файл .env автоматически не читается: экспортировать переменные через терминал или настройки запуска VS Code.

После отдельного согласия пользователя можно использовать совместимый HTTPS API с `BAIKAL_LLM_API_KEY`. Это передаёт выбранные публичные выдержки провайдеру. Точная стоимость зависит от выбранного провайдера и модели: `(input_tokens × input_price + output_tokens × output_price) / 1_000_000` для тарифов за миллион токенов. Тарифы не фиксируются и не выдумываются; перед включением сверить их у провайдера. По умолчанию вызовов и расходов нет. Удалённый URL программно блокируется без явного флага `--allow-remote`; его включение требует отдельного согласия пользователя. Перенаправления запрещены, чтобы локальный сервер не перенаправил запрос во внешний сервис.

Ответ принимается только как JSON с точными ссылками на переданные source_id/page и подстроками цитат. Неподтверждённые ссылки отклоняются. Выход сохраняется как **неопубликованный черновик** в ignored `data/wiki_updates/llm_drafts/`, потому что наличие цитаты ещё не доказывает, что она логически поддерживает утверждение. Автоматического повышения статуса числовых наблюдений нет. В тестах проверены валидатор, блокировка удалённого вызова и весь HTTP-путь на локальном тестовом сервере с фиксированным ответом. Это проверка интеграции, не работы настоящей языковой модели. Инференс реальной локальной модели и внешние API в этой среде не запускались.

В спринте энциклопедии 14 новых статей подготовлены на основе выбранных сохранённых страниц. Платный API и локальный модельный сервер не запускались. Находящиеся в Git статьи и их основания можно читать без LLM; для дальнейшей автоматической генерации сохраняется описанный выше отдельный режим черновиков и проверки.


## Предложения по обновлению

Рекомендуемый режим: `python -m baikal synthesize TOPIC_ID --proposal PROPOSAL_ID` после `propose-updates`. Пакет содержит до 12 точных фрагментов с версиями источников; перед запросом проверяются его целостность, актуальность и цитаты. Старый режим `synthesize air` по-прежнему использует короткие выдержки компилятора; они могут не представлять всё содержание темы и требуют отдельной оценки пригодности.

Команда больше не записывает модельные черновики в `wiki/syntheses/` и не обновляет каталог или наблюдения. Результат и предыдущие версии целевых статей сохраняются по контрольным суммам; разные ответы не перезаписывают друг друга. Публикация после содержательной проверки — отдельное редакционное действие.

Содержательная проверка существующей Wiki использует автоматизированный LLM-метод; её реестр не означает запуск встроенного локального сервера или экспертную рецензию. В текущей среде исполняемые файлы Ollama/llama-server/llama-cli, GGUF-модель в рабочем каталоге и порт 11434 не обнаружены. Реальный локальный инференс не выполнялся. Unit-тесты с синтетическими ответами проверяют транспорт и сохранность, а не качество модели. План настоящего теста и протокол опыта: [UPDATE_WORKFLOW.md](UPDATE_WORKFLOW.md).
