# Контролируемое развитие LLM Wiki

Обновление разделяет получение источника, обнаружение фрагментов, предложение изменений, семантическую проверку и публикацию. Автоматическое совпадение цитаты не даёт права публиковать вывод или добавлять число в reviewed набор.

## Готовность цепочки

| Возможность | Текущий результат и ограничения |
| --- | --- |
| Получение нового доклада | `discover`, `add-source`, `ingest`, `update`: существующие HTTPS-загрузка, SHA256, неизменяемые оригиналы и возобновление. В этом спринте новые документы по сети не загружались; неизменный PDF проверен тестом повторного использования без сети. Официальная подлинность — отдельный этап. |
| Ранее неизвестные сведения | Новые/изменившиеся постраничные фрагменты обнаруживаются по контрольным точкам. Текстовая новизна не означает семантически новый научный факт. Известные цитаты отмечаются отдельно. |
| Связанные темы | Лексические правила `config/update_rules.json` связывают фрагменты с существующим каталогом. Нет совпадения — явное сообщение о необходимости ручного тематического разбора. Полнота маршрутизации не гарантируется. |
| Предложения обновления | `propose-updates` формирует ограниченные пакеты со ссылками, SHA256, цитатами и предыдущими версиями статей. Год доклада сохранён; период наблюдения остаётся неизвестным до проверки, а не копируется из года доклада. |
| Новая статья | Для темы очереди создаётся кандидат. Наличие двух разных PDF (разные SHA256, не два зеркала одного файла) отмечает минимальный размер пакета, но не независимость доказательств и не достаточность для статьи. Содержательный черновик может подготовить настроенная LLM; реальный инференс ещё не проверен. Публикация отдельная. |
| Противоречия | Показываются смена версии источника и связанные известные проблемы реестра. Это сигналы для сверки. Автоматическое обнаружение новых научных противоречий по смыслу не реализовано и не имитируется числовым regex. |
| Предыдущие версии | Полный Markdown затрагиваемой статьи, включая HUMAN NOTES, сохраняется по SHA256 в `data/wiki_updates/versions/`. Старые пакеты неизменяемы; новая версия источника не перезаписывает прежнюю. История опубликованных статей дополнительно сохраняется в Git. |
| Журнал | Новые предложения и модельные черновики добавляются в локальный `events.jsonl` с датой/ID. После содержательной проверки итоговые изменения и решения записываются в `wiki/LOG.md`, реестры и Git. |
| Непроверенная публикация | Предложения и LLM-ответы сохраняются в ignored `data/wiki_updates/`; команда синтеза не изменяет опубликованные статьи, каталог, проверенные наблюдения или их происхождение. |

## Пример после получения нового документа

Сначала проверить его происхождение и добавить в реестр. Для **нового** источника выполнить обычный `ingest --source SOURCE_ID`; готовые страницы неизменившихся источников повторно не извлекать.

```bash
python -m baikal propose-updates --source SOURCE_ID --limit 20
# Необязательно: выбрать конкретные физические страницы
python -m baikal propose-updates --source SOURCE_ID --pages 26 27 --limit 20
```

В ответе — ID и пути предложений. Повторный вызов пропускает те же контрольные точки. Обрабатывается не более указанного количества изменившихся страниц одного источника за вызов. Ошибочные/отсутствующие страницы сообщаются и не получают статус успешно просмотренных. Изменение правил, года/статуса источника или границ тематического раздела позволяет пересмотреть страницы. Фильтрация вводных страниц эвристическая: пригодность выдержек нужно проверить перед синтезом. Пакет содержит максимум 12 фрагментов; это ограниченная выборка для дальнейшего анализа, не полная обработка содержания источника. Уже сохранённые пакеты остаются доступными.

При наличии локальной модели можно отдельно подготовить содержательный черновик:

```bash
export BAIKAL_LLM_URL=http://127.0.0.1:11434/v1/chat/completions
export BAIKAL_LLM_MODEL=qwen2.5:7b
python -m baikal synthesize TOPIC_ID --proposal PROPOSAL_ID
```

Модель и сервер устанавливаются отдельно; см. [LLM.md](LLM.md). Источники передаются как недоверенные данные, не инструкции. Проверяются соответствие темы/хеша пакета, актуальность SHA256 источников и наличие точных цитат в контрольных точках; затем ссылки ответа сверяются с переданными доказательствами. Содержательно ложное утверждение с существующей цитатой всё равно может пройти такой валидатор, поэтому результат остаётся черновиком вне Wiki. Платный API без отдельного согласия не используется.

Перед публикацией необходимо сопоставить каждое утверждение со страницей, установить период, территорию, единицу и метод, разрешить либо явно сохранить противоречия. Затем обновить статью, связи, реестры проверки/происхождения и каталог при добавлении новой темы, выполнить lint и тесты. Статус специалиста возможен только после реального подтверждения человеком. Команды автоматического принятия/публикации предложений сейчас нет.

Для явного редакционного решения добавлены `prepare-change` и `apply-change`: подготовка не меняет статью, применение требует отдельного решения, привязанного к хешу полного дополнения и исходной версии. Прежние факты и HUMAN NOTES сохраняются; источники дополняются, а прежняя научная проверка не переаттестовывается автоматически. Изолированные синтетические тесты проверяют принятие, запрет устаревших версий и откат записи. Реального человеческого одобрения в спринте не было; тестовые решения запрещены в настоящем репозитории. Инструкция: [LLM_EVALUATION.md](LLM_EVALUATION.md).

## Воспроизводимый опыт

```bash
python scripts/check_update_workflow.py
# Сохранить компактный протокол:
python scripts/check_update_workflow.py --output datasets/update_workflow_test.json
```

Опыт использует три реально сохранённых текста: 2016/PDF 222, 2024/PDF 67, 2015/PDF 26. Во временном каталоге моделируется их поступление; копируются существующие статьи, реестры и наблюдения. Получены **10 предложений по семи темам**, без публикации. Повтор не создал новых предложений; все 22 статьи и JSON/CSV наблюдений остались идентичными копиям. Предыдущие версии затрагиваемых статей сохранены. SHA256 и страницы приведены в [протоколе](../datasets/update_workflow_test.json). Непустые ручные заметки дополнительно проверяются отдельным синтетическим тестом.

Этот опыт **не является получением нового доклада**, тестом научной новизны или генерацией полноценной статьи. Он не вызывает модель и не использует HTTP-заглушку. Отдельные unit-тесты транспорта используют явно синтетические ответы и проверяют только протокол, сохранность и отклонение неподдержанных ссылок.

В среде не обнаружены исполняемые файлы Ollama/llama-server/llama-cli, GGUF-модель в рабочем каталоге и слушающий порт Ollama 11434. Настоящая локальная языковая модель не запускалась. Это ограниченная проверка доступности, а не утверждение об отсутствии любых возможных моделей в системе.

## Следующий тест с настоящей моделью

Зафиксировать модель, её контрольную сумму, версию сервера, параметры и ресурсы; выполнить один ограниченный пакет. Сохранить вход, сырой результат и время/ресурсы локально, проверить год, территорию, причинность, противоречия и полноту поддержки каждого утверждения. Ошибки цитирования и семантические ошибки считать отдельно. Публиковать только проверенный результат с обновлением реестров; наличие успешного HTTP 200 не считать качеством модели.
