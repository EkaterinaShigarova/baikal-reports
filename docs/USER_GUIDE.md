# Моя памятка по Baikal LLM Wiki — первый черновик

Это рабочая памятка, а не окончательное руководство. Проект выполняется в рамках исследовательской работы автора в ИДСТУ СО РАН. Официальное одобрение результатов институтом не заявляется. Позже отдельно потребуются окончательная памятка, справочник основных таблиц и подробная инструкция для Windows и Visual Studio Code.

## 1. Что это и зачем нужно

Baikal LLM Wiki помогает собирать сведения об экологическом состоянии Байкала из государственных докладов. Wiki — это связанные статьи: из статьи можно перейти к другой теме и к источнику утверждения. Цель — сохранить проверяемые знания, а не просто получить ответ в чате.

В сохранённой коллекции — 11 документов, 3878 обработанных страниц и 22 аналитические статьи. Целевой период проекта — 2003–2026 годы; это не означает, что доклады за все эти годы уже найдены. Фактический список — [SOURCES.md](../SOURCES.md).

## 2. Что делает программа, а что — языковая модель

Программа скачивает PDF, сохраняет оригиналы, извлекает текст и таблицы, организует поиск, проверяет ссылки и сохраняет промежуточные результаты страниц. Она умеет обнаруживать многие ошибки, но совпадение цитаты ещё не доказывает правильность вывода.

Языковая модель Qwen пытается выделять факты и предлагать изменения статей. Она может перепутать год, показатель или смысл таблицы. Её ответы остаются черновиками. Корректный JSON и успешные программные проверки не означают научную достоверность. Автоматическая сверка не заменяет рецензию научного специалиста.

## 3. Для чего нужны Google Drive и GitHub

**Google Drive** хранит доступные исходные доклады: [папка документов](https://drive.google.com/drive/folders/1WokrBQQKYGPQstIU7Xg8x8EX_zJKpL6M). Это место передачи файлов. Само наличие PDF в папке не подтверждает его соответствие официальной публикации ведомства.

**GitHub** хранит код, статьи, небольшие таблицы, документацию и историю изменений. Рабочая ветка проекта — `feat/baikal-llm-wiki`. Ветка — отдельная линия изменений, где можно проверить работу до переноса в основную версию `main`. Большие PDF и веса модели в GitHub не загружаются.

## 4. Где находятся PDF

Десять докладов о Байкале за 2015–2024 годы получены из папки Drive. Ещё один документ — обзор Росгидромета за 2025 год; официальный адрес указан в [SOURCES.md](../SOURCES.md) и [config/sources.json](../config/sources.json).

В подготовленной рабочей среде скачанные оригиналы лежат в `data/raw/`. Имя каждого файла — длинная контрольная сумма SHA256 и окончание `.pdf`. По полю `sha256` в реестре можно узнать нужное имя. Оригиналы менять нельзя.

Папки `data/` нет в GitHub: она специально исключена. Если скачать только репозиторий на новый компьютер, PDF, полные результаты страниц, поисковый индекс и модель сами там не появятся. Существующую рабочую папку `data/` следует отдельно сохранять в резервной копии.

## 5. Где находятся статьи

Начните с [wiki/catalog.md](../wiki/catalog.md): это каталог разделов и подтем. Общий вход — [wiki/index.md](../wiki/index.md).

Все 22 аналитические статьи находятся в `wiki/syntheses/`. Например: [байкальский осётр](../wiki/syntheses/baikal-sturgeon.md), [нерпа](../wiki/syntheses/baikal-seal.md), [авандельта Селенги](../wiki/syntheses/selenga-sediments.md). Папка `wiki/topics/` содержит тематические страницы с выдержками, а `wiki/sources/` — страницы отдельных документов. Эти виды страниц не следует считать одинаковыми по глубине анализа.

Год доклада может отличаться от года наблюдения.

## 7. Как открыть статью и проверить источник

1. На GitHub выберите ветку `feat/baikal-llm-wiki`, откройте каталог и нужную статью. Файлы `.md` показываются как обычный текст с заголовками.
2. Найдите рядом с утверждением ссылку вида `drive-…:p26`. Она ведёт к странице документа в `wiki/sources/`.
3. Откройте ссылку на оригинальный PDF на странице источника. Если GitHub не показывает очень длинный файл источника, откройте его локально в редакторе или найдите оригинал через SOURCES.md.
4. Перейдите к указанной **физической странице PDF** — номеру, который показывает просмотрщик. Напечатанный номер на листе может отличаться из-за обложки и вводных страниц.
5. Сравните не только число, но и заголовок, год, территорию, единицу, подпись столбца и примечание. Если проза и таблица расходятся, сохраняются оба варианта, а не выбирается удобный.

Проверить точность цитаты недостаточно: например, выпуск молоди не доказывает её выживаемость, а план реконструкции не означает выполненную реконструкцию.

## 8. Что работает, а что экспериментально

Работают загрузка и сохранение оригиналов, обработка страниц с продолжением после остановки, извлечение текста/таблиц/изображений, распознавание сканов, поиск по локальному индексу и проверки ссылок. Извлечение сложных таблиц требует дополнительной сверки. Существующий веб-интерфейс сохранён, но в текущих спринтах не развивается.

Экспериментальны содержательное извлечение фактов моделью, определение новизны и предложения обновления. Режим source-first означает «сначала прочитать источник, затем сравнить проверенные факты со статьёй». Его реальные результаты смотрите в начале [LLM_EVALUATION.md](LLM_EVALUATION.md); положительные программные тесты не заменяют опыт с настоящей моделью.

## 9. Как безопасно добавить новый доклад

Это действие меняет рабочие файлы. Перед началом сохраните резервную копию всей рабочей папки, включая `data/`, и проверьте рабочую ветку. Команды вводятся в терминале из папки проекта с установленным Python-окружением; его подготовка описана в [README.md](../README.md). Подробная отдельная инструкция Windows/VS Code ещё предстоит.

Сначала найдите настоящий официальный PDF, проверьте титул, ведомство и отсутствие дубликата в SOURCES.md. Не подставляйте год только из имени файла. Загрузка в Drive сама по себе не добавляет готовую статью в Wiki.

Существующие параметры команд можно проверить без загрузок:

```bash
python -m baikal add-source --help
python -m baikal ingest --help
python -m baikal status
```

Регистрация официального адреса выполняется командой ниже. **Это шаблон, не готовый адрес. Замените слова в верхнем регистре своими значениями; не запускайте строку без замены.** Команда принимает только настроенные официальные домены. Регистрация не скачивает PDF и не доказывает его подлинность.

```bash
python -m baikal add-source --url "ПРОВЕРЕННАЯ_HTTPS_ССЫЛКА_НА_PDF" --name "НАЗВАНИЕ_С_ТИТУЛА"
```

Программа напечатает ID источника. Для первого просмотра обработайте только три страницы **нового** документа, подставив этот ID:

```bash
python -m baikal ingest --source "ID_НОВОГО_ИСТОЧНИКА" --workers 2 --limit-pages 3
python -m baikal status
python -m baikal lint
```

Три страницы — проба, не обработка всего документа. Проверьте полученный текст/титул/таблицы. После проверки можно обработать оставшиеся страницы того же нового документа:

```bash
python -m baikal ingest --source "ID_НОВОГО_ИСТОЧНИКА" --workers 2
```

Команды и параметры существуют в текущем коде; регистрация дополнительно проверяется в изолированной копии, обработка документов уже использовалась для существующей коллекции. В текущем спринте новые PDF не скачивались и готовые страницы повторно не обрабатывались. Доступность конкретного будущего URL заранее не гарантируется. Не запускайте два ingest одновременно.

`ingest` также перестраивает страницы выдержек/индекс Wiki; это не создание новой проверенной аналитической статьи языковой моделью. Просмотрите изменения и ошибки до сохранения в GitHub. Не включайте PDF в commit. Не используйте `--refresh`, массовый `update` или `ingest` без `--source` как обычный первый шаг: они затрагивают большую коллекцию. Для новой аналитической статьи и числовых наблюдений нужна отдельная проверка.

## 10. Чего нельзя делать без проверки

Не изменяйте исходные PDF, не удаляйте `data/`, не переносите числовые кандидаты или модельные ответы в observations. Не исправляйте противоречащие источнику числа по догадке. Не стройте вывод о тенденции из несопоставимых измерений. Не объявляйте статью проверенной специалистом без реальной рецензии.

Не запускайте `apply-change` с придуманным одобрением. Не публикуйте ключи, пароли, большие PDF или модель. Не включайте внешний или платный LLM API без отдельного решения. Все эксперименты сначала сохраняются вне действующей Wiki.

## 11. История изменений и проверки

[PROGRESS.md](../PROGRESS.md) содержит отчёты спринтов. [wiki/LOG.md](../wiki/LOG.md) — журнал изменений базы знаний. На GitHub раздел **Commits** показывает сохранённые изменения выбранной ветки; **Actions** — запуски автоматических проверок, если они включены. Зелёная отметка означает успешный программный тест, а не научное одобрение.

В установленной рабочей среде проверки можно повторить:

```bash
python -m unittest discover -s tests -v
python -m baikal lint
python scripts/check_scientific_review.py --require-local
python scripts/check_encyclopedia.py --require-local
python scripts/verify_evidence.py
```

Последним трём нужны локальные сохранённые страницы. В чистом GitHub checkout их нет; отсутствие файлов не означает повреждение публичных статей. Итоги LLM-опытов и ссылки на небольшие отчёты находятся в LLM_EVALUATION.md; полные ответы и журналы хранятся в локальной `data/llm-evaluation/` и `data/wiki_updates/`.

## 12. Мини-словарь

| Слово | Простое объяснение |
| --- | --- |
| LLM | Языковая модель: программа, составляющая текст по входным данным; может ошибаться |
| Qwen | Семейство языковых моделей; в проекте установлена локальная версия 7B |
| Markdown | Простой формат текста с заголовками и ссылками; файлы `.md` |
| CSV | Текстовый файл таблицы; строки и столбцы можно открыть в табличном редакторе |
| JSON | Формат записей с именованными полями, например годом и источником; удобен программе |
| GitHub | Сервис для хранения проекта и истории изменений; сам по себе не запускает локальные PDF и модель |
| commit | Сохранённый набор изменений с собственным номером, пояснением и местом в истории |
| SHA256 | Контрольная сумма — «отпечаток» файла; помогает понять, изменился ли он, но не доказывает истинность содержания |
| OCR | Распознавание текста на изображении, например на сканированной странице |
