# Экспериментальный режим source-first

Режим разделяет извлечение из первоисточника и оценку новизны относительно Wiki. Он использует существующие сохранённые тексты, неизменные пакеты `save_packet`, архивирование полной версии статьи, строгую проверку цитат и установленный локальный runtime. Статьи и observations не изменяются. Условия ограниченного опыта заданы в [протоколе](SOURCE_FIRST_PROTOCOL.md), результаты — в [LLM_EVALUATION.md](LLM_EVALUATION.md).

## Границы автоматизации

Первый запрос содержит только прежние source_fragments: без статьи, известных вопросов реестра и эталонных ответов. Код проверяет структуру, ID, точную цитату, числовые токены и явное основание года. Несоответствующие записи остаются в rejected вместе с причиной. Совпадение числа или цитаты не доказывает правильность привязки показателя/единицы/территории, атомарность или отсутствие ложной причинности.

Поэтому между запросами необходима отдельная содержательная сверка каждого допустимого факта и предполагаемого противоречия с первоисточником. Решения `supported`/`rejected` привязаны к SHA256 всего результата извлечения и полному набору fact-ID, сохраняются отдельно и не могут переписать факт. `supported` означает допуск к экспериментальному сравнению с Wiki, не статус проверенного наблюдения или научного специалиста. В данном режиме `review_kind=source_comparison_non_expert`, `expert_review=false`; для настоящей экспертной рецензии этого недостаточно.

Второй запрос получает только допущенные неизменные факты и их цитаты, снимок прежней статьи и известные вопросы. Модель возвращает только решения по ID. Свободный текст факта, источники и новые ID в ответе запрещены. Для повтора/противоречия нужна точная подстрока статьи; каждый ID и каждое проверенное противоречие должны быть учтены. Правильность самой классификации проверяется отдельно, а не выводится из соответствия JSON.

Для метки `new_detail` программа копирует исходный факт в `data/wiki_updates/source_first_drafts/`. Это отдельный карантин экспериментальных предложений: прямой путь в существующие `prepare-change`/`apply-change` не добавлен. Для переноса необходимы содержательная редакционная сверка, адаптация в штатный контракт дополнения, проверка актуальности источников/статьи и отдельное решение. Нельзя использовать выход второго этапа как новую фактическую запись.

## Запуск без скачивания модели

Нужны установленный проект (`python -m pip install -e .`), сохранённые исходные raw-run предыдущего опыта, локальные контрольные точки, два проверенных shard 7B и прежний AVX2 llama.cpp. Чистый Git checkout без ignored данных не воспроизводит реальные генерации сам по себе. Он позволяет выполнить синтетические тесты и изучить публичный отчёт.

```bash
python scripts/evaluate_source_first.py --prepare \
  --output data/llm-evaluation/source-first-prepared.json
# EXPERIMENT_ID взять из сохранённого результата подготовки.
python scripts/evaluate_source_first.py --extract --experiment EXPERIMENT_ID \
  --output data/llm-evaluation/source-first-extract.json
```

Пример структуры отдельного файла решений после реального прочтения фактов и цитат:

```json
{
  "experiment_id": "EXPERIMENT_ID",
  "cases": {
    "TOPIC_ID": {
      "bundle_sha256": "SHA256_PROGRAMMATICALLY_CHECKED_BUNDLE",
      "review_kind": "source_comparison_non_expert",
      "expert_review": false,
      "fact_decisions": {
        "FACT_ID": {
          "status": "rejected",
          "reason": "Указать конкретную причину после сверки.",
          "limitations": ["Не является экспертной рецензией."]
        }
      },
      "conflict_decisions": {}
    }
  }
}
```

Включить оба случая и решение по каждой программно допустимой записи. Этот шаблон не подтверждает факт, не является редакционным одобрением и не должен автоматически заполняться значением supported.

```bash
python scripts/evaluate_source_first.py --compare --experiment EXPERIMENT_ID \
  --extraction data/llm-evaluation/source-first-extract.json \
  --review data/llm-evaluation/source-first-source-review.json \
  --output data/llm-evaluation/source-first-compare.json
```

При отсутствии поддержанных фактов сравнение не выполняется. Перед каждым HTTP-запросом эксклюзивно создаётся маркер попытки для пары случай/этап. Повтор с тем же manifest запрещён даже после ошибки или аварии. Новый manifest не разрешает неучтённые повторы того же научного опыта: любой следующий запуск требует нового обоснованного протокола. Всего в текущем опыте допускаются максимум четыре генерации, без автоматических повторов. Ни downloader, ни OCR в этих командах не вызываются. Loopback-запросы обходят системные прокси и не используют переменные внешних API.

## Аудит

`source_first_experiments/` содержит immutable manifest с SHA256 протокола, кода, промптов и прежних данных. `source_first_inputs/`, `source_first_runs/`, `source_first_reviews/` сохраняют запросы, сырые ответы, программные отказы и промежуточные решения. Полные предыдущие статьи архивируются вместе с HUMAN NOTES. Все эти папки находятся внутри ignored `data/wiki_updates/`. Запросы к модели выполняются только локально; платных API нет. Измерения двух фаз учитывают два старта сервера; время промежуточной сверки в инференс не входит.
