# Baikal LLM Wiki

Научно-исследовательский проект экологического мониторинга озера Байкал и Байкальской природной территории по государственным докладам. Целевой период — **2003–2026**, фактическое покрытие перечислено в [SOURCES.md](SOURCES.md). Непроверенные годы не подменяются вымышленными документами.

Проект выполняется автором в рамках работы в Институте динамики систем и теории управления имени В. М. Матросова СО РАН (ИДСТУ СО РАН). Официальное одобрение или публикация результатов институтом не заявляются.

Система загружает PDF, сохраняет неизменяемые оригиналы, обрабатывает страницы с возобновлением, создаёт постоянную связанную Markdown Wiki и показывает проверенные данные в локальном веб-приложении. Базовый режим бесплатен и не требует LLM API. [Методика Karpathy и границы реализации](docs/METHODOLOGY.md).

## Что уже работает

- Обнаружение PDF в публичной папке Google Drive, проверка официальных каталогов и регистрация дополнительных официальных PDF.
- Потоковая загрузка, SHA256, проверка размера/формата, хранение версий, обработка каждой страницы независимо.
- Текст, заголовки и блоки, таблицы PyMuPDF/pdfplumber, кандидаты продолжений таблиц, изображения, подписи и превью. OCR Tesseract rus+eng для страниц с плохим текстовым слоем.
- SQLite FTS для поиска по страницам, постоянные Wiki-страницы источников, тем и сущностей; индекс, журнал, query с сохранением, lint.
- Набор **168 реальных значений**, прошедших автоматизированную сверку переноса по тексту и изображениям документов 2018, 2024 и 2025 годов; отдельные статусы происхождения и сопоставимости.
- Веб-приложение: обзор, Wiki, поиск, фильтры, интерактивные графики, сравнение годов, таблицы, просмотр страниц и ссылки на оригиналы.
- Необязательный LLM-синтез ограниченных пакетов доказательств с проверкой цитат и сохранением черновиков.

**Обработаны 11 документов, 3878 страниц:** 10 докладов о Байкале за 2015–2024 годы и официальный общероссийский обзор Росгидромета за 2025 год. В Wiki — 22 аналитические статьи, включая 14 новых статей тематической энциклопедии, плюс страницы источников, каталоги доказательств и сущности. [Сводка обработки](datasets/processing_summary.json).

Полный фактический отчёт о выполнении: [PROGRESS.md](PROGRESS.md). Это исследовательский инструмент, а не аттестованная система государственного мониторинга. Автоматически извлечённые таблицы и числа требуют проверки; их качество не объявляется идеальным.

## Быстрый старт в Visual Studio Code

### 1. Получить проект

Установите Python 3.11 или новее, Git и VS Code с расширением Python. Клонируйте репозиторий и откройте папку в VS Code:

```bash
git clone https://github.com/EkaterinaShigarova/baikal-reports.git
cd baikal-reports
git switch feat/baikal-llm-wiki
code .
```

После слияния Pull Request переключаться на отдельную ветку не требуется.

### 2. Создать окружение

В терминале VS Code (меню «Терминал → Создать терминал»):

```bash
python -m venv .venv
```

Linux/macOS:

```bash
source .venv/bin/activate
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Если политика PowerShell не позволяет активацию, используйте `.\.venv\Scripts\python.exe` вместо `python`; изменение политики не обязательно. Выберите созданное окружение через команду VS Code **Python: Select Interpreter**.

```bash
python -m pip install -r requirements.lock -e ".[test]"
python -m unittest discover -s tests -v
python -m baikal build
python -m baikal serve
```

Откройте адрес, напечатанный сервером, в браузере на своём компьютере (по умолчанию порт 8000). Остановка — `Ctrl+C`. Обзор, Wiki и компактный набор данных доступны из Git сразу; полнотекстовый поиск и просмотр PDF наполняются после ingest. Большие PDF в Git отсутствуют.

### 3. OCR и документы

Установите **Tesseract OCR 5**: Linux — пакет `tesseract-ocr`, macOS — `brew install tesseract`, Windows — сборка Tesseract с добавлением исполняемого файла в PATH. Затем:

```bash
python scripts/setup_ocr.py
python -m baikal discover --official
python -m baikal ingest --source drive-1QKhC57MB-qveIXhYWKGfSOkTmzdFw_mJ --workers 2
```

Первый пример обрабатывает весь доклад за 2018 год, 342 страницы. Все найденные документы:

```bash
python -m baikal ingest --workers 2
```

Нужны свободный диск и время: оригинальная коллекция близка к 1 ГБ; изображения, превью и промежуточные результаты увеличивают расход. Рекомендуется не менее 10 ГБ свободного места и 4 ГБ RAM. Большие сканы с OCR могут обрабатываться значительно дольше текстовых PDF. Не запускать два ingest одновременно в одной рабочей копии.

После прерывания повторите ту же команду: завершённые страницы с совместимой версией извлекателя сохраняются. `--limit-pages 10` подходит для пробного запуска и отмечается как частичная обработка. `--retry-errors` повторяет ошибки OCR. Установка языковых моделей сохраняет TLS и проверяет SHA256.

## Обновления и Wiki

```bash
python -m baikal update --workers 2
python -m baikal status
python -m baikal query "качество воды" --save
python -m baikal lint
python -m baikal export-candidates
```

`export-candidates` сохраняет локальный JSONL всех числовых кандидатов с контекстом в `data/exports/`; неизвестные год, территория и показатель остаются null.

`update` перечитывает папку, добавляет новые документы, обрабатывает изменившиеся и обновляет Wiki/индекс. Для принудительного сравнения содержимого удалённого файла, в том числе изменения при одинаковом размере, используйте `--refresh`: PDF заново скачивается и сравнивается по SHA256, неизменившиеся страницы не пересчитываются. Различные версии исходника остаются на диске по разным хешам.

Для еженедельного запуска на Linux можно добавить в cron команду `cd /путь/baikal-reports && .venv/bin/python -m baikal update >> /путь/baikal-update.log 2>&1`. На Windows аналогичную команду запускает Планировщик заданий. Не планируйте перекрывающиеся запуски.

`wiki/` можно открыть в Obsidian или VS Code. Статьи содержат источники и страницы; `wiki/index.md` — входная точка, `wiki/LOG.md` — журнал. Автоматический ingest обновляет выдержки и связи. Для синтезов сохраняются хеши использованных источников; lint предупреждает об устаревании при смене версии. Ручные замечания после `<!-- HUMAN NOTES -->` сохраняются. Новые аналитические статьи размещаются в `wiki/syntheses/`. [AGENTS.md](AGENTS.md) описывает правила поддержания базы знаний.

Оригинальная методика не сводится к RAG: знания сохраняются и изменяются в Wiki, включая результаты запросов. Бесплатный компилятор выдержек не выдаётся за семантический LLM-синтез. Для синтеза предусмотрен [настраиваемый локальный/API-режим](docs/LLM.md); результат требует содержательной проверки.

## Официальные источники

`discover --official` проверяет разрешённые официальные каталоги и сохраняет результаты в реестр. Найденная PDF-ссылка — кандидат, не доказательство содержания. После проверки ссылки можно зарегистрировать документ:

```bash
python -m baikal add-source --url 'https://www.mnr.gov.ru/ПОДТВЕРЖДЁННЫЙ-ПУТЬ.pdf' --name 'Название с титула' --year 2020
```

Это шаблон, не реальный URL. Далее `ingest --source <выданный-id>`. Подлинность зеркала Google Drive не подтверждается только названием файла или наличием слова «государственный». Необходимо сопоставление с публикацией ведомства. Сетевые ошибки и отсутствие доступа перечислены в SOURCES.md; TLS-проверка не отключается.

## Данные и сопоставимость

CSV и JSON: [datasets/](datasets/README.md). Поля: год наблюдения, показатель, значение, единица, территория, документ, SHA256, страница, цитата, метод, период, статус проверки и сопоставимости. Год публикации/доклада хранится отдельно от года наблюдения.

Проверенные значения перенесены из трёх документов; 88 из них — из таблицы 4.7 официального обзора Росгидромета за 2025 год. Это не означает, что отдельные доклады за все соответствующие годы уже найдены. Ряды из разных таблиц и методик автоматически не склеиваются. Столбец confidence описывает уверенность переноса, а не научную достоверность измерения. Кандидаты из других страниц сохраняются локально и не становятся данными графика без рецензирования.

## Структура

```text
baikal/             CLI, загрузка, PDF/OCR, SQLite, Wiki, API
web/                локальный веб-интерфейс без CDN
config/             каталог источников и схема Wiki
datasets/           компактные проверенные CSV/JSON
wiki/               источники, темы, сущности, синтез, запросы, журнал
data/raw/           неизменяемые PDF по SHA256 (не в Git)
data/processed/     страницы, таблицы, изображения, QA (не в Git)
data/baikal.sqlite  полнотекстовый индекс (не в Git)
tests/              тесты контрактов и поведения
```

## Ограничения

Карты, схемы и графики сохраняются как изображения с подписями и статусом human_review. Автоматическая достоверная оцифровка кривых не реализована. Сложные/многостраничные таблицы сохраняются и связываются как кандидаты; без проверки геометрии и структуры их нельзя считать полностью восстановленными. Платный LLM не устраняет эти ограничения. Официальная подлинность и покрытие всех лет остаются отдельными задачами.

Сервер предназначен для локальной работы. Публикация в Интернет потребует отдельной настройки доступа. Секреты задаются переменными окружения; .env, PDF и data/ исключены из Git. Исходные PDF не изменяются.

## Проверка результатов и таблиц

После получения локальной коллекции:

```bash
python scripts/collection_report.py --verify-hashes
python -m baikal audit-tables
python scripts/verify_evidence.py
python -m baikal lint
```

Аудит проверяет, не остались ли числа и текст за границами распознанных столбцов. Он повторно читает геометрию страниц, сохраняя готовые OCR/текстовые контрольные точки. Предупреждения доступны при просмотре страниц; отсутствие предупреждения не гарантирует полноту. Подробности: [проверки качества](docs/QUALITY.md).

Браузерная проверка необязательна: установить `playwright` (`python -m pip install playwright`, затем `python -m playwright install chromium`), запустить сервер и выполнить `python scripts/check_browser.py`. Нужна локально обработанная коллекция. Можно указать `CHROMIUM_EXECUTABLE` и `BAIKAL_TEST_URL`. Для обычного использования браузерная библиотека не нужна.

## Тематическая энциклопедия

[Каталог](wiki/catalog.md) организует знания в шесть разделов и 15 подтем. В нём 22 опубликованные аналитические статьи и две темы в очереди с найденными страницами и явными пробелами. Каждая тема имеет статус обеспеченности источниками; он не означает научной сертификации или автоматического разрешения сравнивать числа.

На сайте откройте «База знаний»: дерево разделов ведёт к статьям, поиск над деревом ищет по их тексту. Например, «синедровый» находит статью о фитопланктоне, хотя этого слова нет в её названии. Ссылку на статью можно скопировать из адресной строки; работают перезагрузка и возврат назад. При наличии локального PDF ссылка на цитируемую страницу открывает готовый просмотр документа. Поиск по докладам остаётся отдельным инструментом.

Структура задаётся в `config/encyclopedia.json`. Команда `python -m baikal build` обновляет каталог и индекс Wiki, сохраняя ручные заметки. Для проверки цитат: `python scripts/check_encyclopedia.py --require-local` (требуются сохранённые страницы); обычный `python -m baikal lint` также проверяет каталог и реестр доказательств. Полные тексты выбранных страниц в `datasets/encyclopedia_evidence.json` позволяют проследить основания новых статей. Автоматическая проверка наличия текста не заменяет содержательную экспертизу.

Для браузерной проверки энциклопедии при запущенном сервере: `python scripts/check_encyclopedia_browser.py`. Как и общий браузерный тест, команда требует Playwright/Chromium; адрес сервера задаётся `BAIKAL_TEST_URL`.

## Проверка достоверности знаний

[Отчёт содержательной проверки](docs/SCIENTIFIC_REVIEW.md): все **22 аналитические статьи** прошли автоматизированную сверку в объёме **107 существенных смысловых блоков**, по 64 страницам 11 документов. Это не научная экспертиза. Статусы и открытые вопросы каждой статьи доступны в [реестре Wiki](wiki/topics/knowledge-quality.md). Наличие 168 сверенных наблюдений не разрешает автоматически сравнивать любые ряды.

Точные цитаты, физические страницы, SHA256, периоды наблюдений и причины изменений сохранены в `datasets/scientific_review_claims.json`; охват и версии — в `datasets/scientific_review.json`. Команда `python scripts/check_scientific_review.py --require-local` проверяет происхождение, а не научную истинность. Изменение текста/источника делает проверку устаревшей; повторная сборка сохраняет исправления и ручные заметки.

## Контролируемое обновление Wiki

`python -m baikal propose-updates --source SOURCE_ID --limit 20` готовит предложения по сохранённым страницам, не вызывая модель и не публикуя изменения. Предложения, LLM-черновики и предыдущие версии статей находятся локально в ignored `data/wiki_updates/`. Семантическую новизну, противоречия и готовность к публикации лексические правила не удостоверяют.

[Процесс обновления и его ограничения](docs/UPDATE_WORKFLOW.md) включает воспроизводимый опыт на трёх реальных сохранённых страницах. `python scripts/check_update_workflow.py` проверяет подготовку предложений, повторный запуск и сохранность статей/наблюдений. Опыты Qwen 1.5B дали по два отклонённых ответа; Qwen 7B прошла программные проверки в 2/2 случаях, но полный смысловой допуск обновления — 0/2; платные API не используются по умолчанию.

[Настоящий LLM-эксперимент](docs/LLM_EVALUATION.md): модели Qwen2.5-1.5B и 7B Q4_K_M загружены с проверкой SHA256. На одинаковых v2-входах 7B лучше соблюдает формат: 2/2 программно принятых ответа против 0/2. Смысловая атрибуция и новизна остаются ненадёжными, полностью пригодных обновлений 0; автоматическое развитие Wiki пока не подтверждено. Ответы и ошибки сохраняются вне Wiki. Для будущих дополнений доступны `prepare-change` и `apply-change` с отдельным редакционным решением, сохранением прежнего текста и ручных заметок. Это не автоматическая публикация и не экспертная рецензия.
